# K PLUS ScamBreak — Complete Connected Demo

[เปิดเดโม](https://blimmy.github.io/kplus-scambreak-demo/?v=journey-v2) · [Repository](https://github.com/blimmy/kplus-scambreak-demo)

มือถือเครื่องเดียวที่กดใช้งานได้ตั้งแต่หน้าแรก ทั้ง **เบรกก่อนโอน** และ **หยุดเงินทันเมื่อรู้ตัว** อยู่ในแอปและสถานะเดียวกัน ไม่ต้องสลับฉากเพื่อเล่นต่อ

## ลองเล่นเส้นทางหลัก

1. หน้าแรก → **โอนเงิน** → เลือกผู้รับตัวอย่าง
2. ใส่ยอดด้วยแป้นตัวเลข พิมพ์เอง หรือเลือกยอดด่วน → **ตรวจสอบข้อมูลการโอน**
3. ยอดที่ใส่จะปรากฏในหน้าตรวจสอบจากสไลด์ → **ตรวจสอบความเสี่ยง**
4. ตอบ “ใช่ / ไม่ใช่” ครบ 3 ข้อ → **ดูคำแนะนำ** → พักรายการ
5. เลือกยกเลิกรายการพร้อมยืนยัน หรือกด **ฉันอาจถูกหลอก**
6. รอเปิดการป้องกัน → **เลือกรายการและแจ้งเหตุ**
7. เลือกรายการก่อนหน้า → เลือกเหตุการณ์และยืนยันความยินยอมในเดโม → ตรวจทาน → ยืนยันแจ้งเหตุจำลอง
8. ติดตามเคส **SB-2026-00128** → ดู/เพิ่มหลักฐานตัวอย่าง → ติดต่อเจ้าหน้าที่จำลอง → ดูขั้นตอนถัดไป
9. กลับหน้าแรกแล้วเปิดติดตามเคสเดิมได้ การป้องกันบัญชียังคงอยู่

ทุกหน้ามีทางย้อนกลับหรือกลับหน้าแรก ปุ่ม “สาธิตครบ” ที่อยู่นอกมือถือสามารถเล่นเส้นทางนี้ให้ดูอัตโนมัติ 24 ขั้น ผู้ใช้กดแทรกเพื่อควบคุมเองได้ทันที

## ความหมายของเงินสองรายการ

| รายการ | สถานะ |
| --- | --- |
| ยอดที่คุณเพิ่งใส่ | ถูกตรวจสอบ/พัก/ยกเลิก **ยังไม่โอนออก** ไม่หักยอดคงเหลือ |
| รายการก่อนหน้า 50,000.00 บาท | ธุรกรรมสมมติจากสไลด์ที่เกิดก่อนเริ่มเดโม เป็นรายการที่เลือกแจ้งเหตุและติดตามเคส |

การแยกสองรายการนี้ทำให้ทั้งสองฟีเจอร์เล่าต่อกันได้โดยไม่สื่อว่าเงินที่พักไว้ถูกโอนไปแล้ว หรือได้เงินก่อนหน้าคืนแล้ว

- countdown `00:45` ย่อให้เล่นจบใน 15 วินาที เมื่อถึงศูนย์ยังพักรายการ ไม่มีการโอนต่ออัตโนมัติ
- สัญญาณผู้รับใหม่/ยอดผิดปกติเป็นเหตุการณ์ตัวอย่างจากสไลด์ ไม่ได้คำนวณคะแนนความเสี่ยงจริง คำตอบ “ไม่ใช่” ไม่ได้ยืนยันว่าปลอดภัย
- ยอดโอนใช้ทศนิยมไม่เกิน 2 ตำแหน่ง มากกว่า 0 และไม่เกินเงินคงเหลือตัวอย่าง เริ่มที่ 123,456.78 บาท
- เปิดโหมดฉุกเฉินแล้วจะหยุดทุกเส้นทางเงินออก แม้กลับหน้าแรก ย้อนหน้า หรือเปิด QR การเริ่มเดโมใหม่เท่านั้นที่จะคืนสถานะปกติ
- เคสยังเป็น “กำลังตรวจสอบ” ไม่ยืนยันการคืนเงินหรืออายัดบัญชีปลายทาง

## ปุ่มอื่นทำอะไรได้

ดูรายการละเอียดที่ [BUTTONS.md](BUTTONS.md)

- บัญชี: แสดง/ซ่อนยอดคงเหลือ และเปิดประวัติรายการ
- เติมเงิน / จ่ายบิล / ถอนเงิน: เลือกยอด → ตรวจทาน → ใบรายการตัวอย่าง → ประวัติในเดโม เปลี่ยนเฉพาะยอดเงินสมมติในหน่วยความจำ
- สแกน: เลือก QR ตัวอย่างแล้วเข้าสู่เส้นทางใส่ยอดเดียวกัน ไม่เปิดกล้องหรืออ่าน QR จริง
- ธุรกรรม / แจ้งเตือน / บริการอื่น ๆ / กระดิ่ง: มีหน้าปลายทางและเปิดรายการ/เคสต่อได้
- ติดต่อ: เลือกหัวข้อแชตจำลอง หรือดูสถานะเชื่อมต่อและวางสายจำลอง
- หลักฐาน: เปิดสลิป ภาพแชต บันทึกการโทร และโปรไฟล์สมมติ เลือกเพิ่ม/เปลี่ยนหลักฐานแล้วจำนวนในเคสอัปเดต
- ความปลอดภัย: ดูอุปกรณ์ จบเซสชันตัวอย่าง ตรวจรายการคำแนะนำ ไม่กรอกรหัสจริง
- AOC: เตรียมสรุปและทำเครื่องหมายในรายการสิ่งที่ต้องทำ ไม่มีการโทรหรือส่งข้อมูลไป AOC

แชตใช้ข้อความสุภาพพร้อมขั้นตอนถัดไปตามแนวทาง Thai Customer Service ไม่สัญญาผลตรวจสอบ ระยะเวลาคืนเงิน หรือความสำเร็จในการอายัดบัญชี

## ควบคุมการนำเสนอ

- เปิดเว็บแล้วกดบนมือถือได้เลย เริ่มต้นไม่เล่นอัตโนมัติ
- **สาธิตครบ** เริ่มเส้นทางตัวอย่างใหม่ตั้งแต่หน้าแรก
- **หยุด / เล่นต่อ** หยุดและเดินต่อทั้ง fade, ripple, countdown, การป้องกันบัญชี, การรับแจ้งเหตุ และการเชื่อมต่อจำลอง
- **← / →** ย้อนกลับ / ทำขั้นตอนถัดไปตามหน้าปัจจุบัน ไม่ข้ามการตรวจฟอร์ม
- **R / เริ่มใหม่** ล้างทุกสถานะและคืนหน้าแรก
- **Space** เล่น/หยุด, **F** เต็มจอ, **H** ซ่อน/แสดงแถบควบคุม
- **เล่นต่อเนื่อง** ใช้กับโหมดอัตโนมัติ ปิดเพื่อหยุดหลังจบแต่ละขั้น
- **ไปยังช่วงของเดโม** เป็นทางลัดภายในแอปเดียว ไม่ล้างสถานะเคส/การป้องกัน
- จอเล็กซูม 150% / 200% และเลื่อนได้ หน้าจอเดิมใช้พิกัดคงที่ ไม่จัดข้อความในภาพใหม่
- สลับแท็บแล้วเดโมจะหยุดรอ รีเฟรชเว็บจะเริ่มใหม่เพราะไม่มีการบันทึกข้อมูล

## เปิดในเครื่องและ Build

ใช้ Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจ:

~~~sh
npm start
~~~

เปิด `http://127.0.0.1:4173/` ผ่าน HTTP server (ไม่ดับเบิลคลิก HTML เพราะใช้ ES modules)

~~~sh
npm test
npm run build
npm run preview
~~~

Build คัดลอกไฟล์ static ไป `dist/` Preview ใช้พอร์ต 4173 เช่นกัน ต้องหยุด server เดิมก่อน หรือกำหนด `PORT` ใหม่

ไฟล์หลัก:

- `src/journey.js` — สถานะเดียวของแอป การตรวจฟอร์ม ประวัติ เคส และนาฬิกา
- `src/screens.js` — หน้าเชื่อมและหน้าปลายทางของปุ่ม
- `src/app.js` — แสดงภาพจากต้นฉบับ hotspot การเปลี่ยนหน้าและควบคุมเดโม
- `src/scenes.js` — พิกัดปุ่มจากสไลด์เดิม
- `assets/phone/` — กรอบและภาพหน้าจอเดิม
- `assets/journey/` — ชิ้นภาพสำหรับหน้าเชื่อมที่ตัดจากต้นฉบับ

## Deploy บน GitHub Pages

ใช้ **Settings → Pages → Deploy from a branch → main → / (root)** เว็บไซต์เป็น static อยู่แล้ว จึงไม่ต้องมี build workflow เพิ่ม GitHub สร้างงาน `pages-build-deployment` ให้เอง และเผยแพร่หลัง push ไป `main`

มี `.nojekyll` และทุก URL เป็นแบบสัมพัทธ์ รองรับ project repository path ไม่มี server routing ใช้ hash แสดงหน้าปัจจุบัน เมื่อ refresh จะคืนหน้าแรกโดยไม่เกิด 404

ไม่รวม PPTX, ไฟล์ Desktop อื่น, credential หรือผลทดสอบใน repository โดย `.work/` และ `dist/` อยู่ใน `.gitignore`

## ขอบเขตและการตรวจสอบ

ไม่มี backend, database, API, analytics, CDN, login, persistent storage หรือการรับรหัสผ่าน PIN OTP / เลขบัญชีจริง มีช่องให้ใส่เฉพาะยอดเงินสมมติ ใช้หลักฐานที่เตรียมไว้ ไม่มี file input, camera, microphone หรือการโทรจริง

สถานะทั้งหมดอยู่ในหน่วยความจำ และทุกภาพเคลื่อนไหวใช้นาฬิกา `requestAnimationFrame` ชุดเดียว Content Security Policy กำหนด `connect-src 'none'` และ `form-action 'none'`

ทดสอบ Chrome ผ่าน Playwright และ Pillow (ไม่ใช่ dependency ของเว็บ):

~~~sh
python -m pip install playwright Pillow
python tests/browser_check.py http://127.0.0.1:4173/
~~~

ตรวจหน้าจอต้นฉบับ, เส้นทางหลักและแขนง, ปุ่มหน้าแรกทุกกลุ่ม, validation, pause/resume/reset, keyboard, fullscreen, resize, mobile touch และ network ภาพ/รายงานอยู่ใน `.work/journey-browser/` ดูผลที่ [VERIFICATION.md](VERIFICATION.md)
